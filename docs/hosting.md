# Hosted catalog and administration

## Supabase setup

1. Create a development Supabase project first. Use separate Supabase projects for Vercel Preview and Production.
2. Apply `supabase/migrations/202611210001_catalog.sql` to the development project through the SQL editor or Supabase CLI. Review it and back up existing business data before applying it to a production project. The migration creates the private catalog schema, database functions, and private image bucket. Keep `bishop_private` out of the project's exposed API schemas.
3. Disable public sign-ups in Supabase Auth. Configure approved site and redirect URLs in Auth and configure mail delivery before relying on invites or password recovery. Use exact URLs such as `https://your-domain.example/admin` and `http://127.0.0.1:5173/admin` for the environments where those flows are used.
4. Invite the initial staff owner through Supabase Auth. After verifying their identity, replace the placeholder in the following statement with the invited account's UUID and run it as the database administrator through the SQL editor.
   
   ```sql
   insert into bishop_private.staff_members (user_id, role, is_active)
   values ('<owner user UUID>'::uuid, 'owner', true);
   ```

5. Copy `.env.example` to `.env.hosted.local` for local hosted development. Set the Supabase project URL and the publishable key. Never place a service-role or secret key in a Vite environment variable. These settings should point at the development project.
6. For each editor, invite a verified email through Auth, then use the owner dashboard's **Settings** panel to grant editor access by user UUID. The invitation opens the initial password form. Staff can also use **Forgot password?** through the Auth email flow. Enable authenticator MFA for staff and test the challenge before launch. The database requires AAL2 for accounts with a verified factor. Check project-level password, MFA, email rate-limit, and recovery settings in the real Supabase environment.

## Day-to-day staff guide

- Open `/admin` and sign in. The hosted dashboard is separate from the Windows Site Editor.
- Go to **Categories** to add or reorder categories. The migration starts with the existing SSDs, RAM, Chargers, and Accessories categories. Deactivating a category hides its products from the public Store without removing their records.
- Go to **Products**, select **Add Product**, and choose a category. Enter confirmed descriptions and specifications. Add a variant with a unique SKU, its actual quantity and threshold, and a selling price if confirmed. Leave price blank to show **Enquire for price**.
- Upload JPEG, PNG, or WebP photos up to 2 MB each. The first image appears on product cards. Set the primary photo, reorder photos, or remove an attached photo before saving. The editor attempts to clean up detached objects it is authorized to delete. Owners can clear unreferenced uploads later in the Supabase Storage dashboard after checking that the paths are unused.
- Select **Save Draft** to keep the listing private or **Publish Product** to make it public. To hide a product, use **Unpublish** or **Archive**. Product slugs remain fixed after creation.
- Update prices and stock on the product form. The database saves the product and its variants together and rejects a stale revision when somebody saves first. The Store reads fresh records on refresh. Exact stock counts stay in staff-only results.
- Owners can manage editor access, business contact details, genuine completed work, and recent audit history. For gallery photos, provide public HTTPS image URLs and use only photos cleared for publication. Editors can manage products, categories, variants, stock, and images.
- Sign out when finished. The hosted dashboard keeps the Supabase session in memory for the current tab and refreshes it while open. Reloading or closing the dashboard requires sign-in again.

## Data access

Catalog tables are in `bishop_private` with RLS enabled and no browser grants. Public and administrative database functions have explicit execution grants and fixed search paths. The public functions project only approved fields. The admin functions check active membership, the stored staff role, and enrolled MFA assurance. Business settings and staff access changes require owner privileges. Product, category, variant, stock, and staff changes generate audit records in the database.

Product Storage uses a private bucket. Anonymous requests can retrieve published product photos through the Vercel image endpoint, which uses the same publishable access as any customer and validates the resulting media. Staff can read managed images, upload under their own user path, and delete eligible unattached objects under the policy. Product disclosure changes take effect on refresh. Direct signed image links generated by staff should be treated as temporary bearer links.

## Vercel deployment

- Connect the feature branch to the intended GitHub/Vercel project after approval. The tracked Vercel configuration runs `npm run build:hosted` and serves `dist/`. Do not run the Windows launcher on Vercel.
- Set `VITE_SUPABASE_URL` and `VITE_SUPABASE_PUBLISHABLE_KEY` for the matching Supabase project in each Vercel environment. These are available to the Vite build and the image function. Set `SITE_ORIGIN` to the canonical HTTPS origin in Production to generate canonical URLs and a static sitemap. Preview builds are marked noindex.
- Add optional `VITE_GOOGLE_REVIEWS_URL` and `VITE_GOOGLE_WRITE_REVIEW_URL` only after verifying they open the correct business review and review-writing views. The site renders Google Maps attribution and the configured buttons. On-site review cards require an approved widget or a Places integration with the correct listing, quota and attribution.
- Verify the preview against a test project first. Test owner and editor sign-in, invalid credentials, recovery, MFA, sign-out, disabled users, and an authenticated non-staff account. Test uploads and removal, publishing, unpublishing, archiving, and concurrent updates. Confirm a public user sees the new price after refreshing without redeployment and cannot see private quantity or unpublished images.
- Check the direct routes, mobile layout, live Maps and WhatsApp redirects, canonical URLs, and sitemap. Submit the production sitemap to Search Console after verifying domain ownership. Product details have stable URLs and server-rendered metadata and descriptions on Vercel. The static sitemap lists the core public pages. Product detail URLs are linked from the Store.
- Confirm owner-approved product prices, stock, images, service details, address, hours, and privacy information before opening the production site. Deploy to production only after owner approval.

## Isolated development tests

`npm test` runs the basic suite. To exercise the migration without a live Supabase project, install `@electric-sql/pglite` in a temporary directory and provide the absolute path to its `dist/index.js` as `BISHOP_PGLITE_MODULE`, then rerun `npm test`. The fixture tests PostgreSQL permissions and product workflows with synthetic Auth and Storage tables. It does not replace the preview checks against Supabase Auth, the actual Storage HTTP API, and Vercel.
